# Security Guide

This document outlines the security measures implemented in the Auth Microservice and best practices for maintaining security.

---

## Implemented Security Measures

### 1. Password Security

| Measure    | Implementation                                     |
| ---------- | -------------------------------------------------- |
| Hashing    | bcrypt with cost factor 10                         |
| Storage    | Salt auto-generated by bcrypt                      |
| Comparison | Constant-time comparison to prevent timing attacks |

```javascript
// Password hashing
const hash = await bcrypt.hash(password, 10);

// Password verification
const isValid = await bcrypt.compare(password, storedHash);
```

### 2. JWT Security

| Measure   | Implementation                                   |
| --------- | ------------------------------------------------ |
| Algorithm | HS256                                            |
| Secrets   | Strong secrets (min 32 characters)               |
| Expiry    | Short-lived access tokens (15 min)               |
| Refresh   | Long-lived refresh tokens (7 days) with rotation |

### 3. Timing Attack Protection

The service implements **DUMMY_HASH** to prevent user enumeration via timing attacks:

```javascript
// Always perform password comparison, even if user doesn't exist
const DUMMY_HASH = bcrypt.hashSync("__timing_mitigation_placeholder__", 10);

export const loginUser = async ({ email, password }) => {
  const user = await userQueries.findOne({ where: { email } });

  if (!user) {
    // Always compare to prevent timing-based enumeration
    await isPasswordCorrect(password, DUMMY_HASH);
    throw new ApiError(401, "Invalid email or password");
  }
  // ...
};
```

### 4. Rate Limiting

| Endpoint Category                                 | Limit                         |
| ------------------------------------------------- | ----------------------------- |
| Auth endpoints (register, login, forgot-password) | 10 requests / 15 minutes / IP |
| Refresh token                                     | 20 requests / 15 minutes / IP |
| All others                                        | Unlimited                     |

```javascript
// In auth.routes.js
const authLimiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15 minutes
  max: 10, // 10 requests
  keyGenerator: (req) => req.ip,
  handler: (_, __, ___, options) => {
    throw new ApiError(429, "Too many requests. Please try again later.");
  },
});
```

### 5. Cookie Security

Refresh tokens are stored in httpOnly cookies with security flags:

```javascript
const COOKIE_OPTIONS = {
  httpOnly: true, // Not accessible via JavaScript
  secure: process.env.NODE_ENV === "production", // HTTPS only in prod
  sameSite: "strict", // CSRF protection
  maxAge: 7 * 24 * 60 * 60 * 1000, // 7 days
};
```

### 6. CORS Configuration

CORS is configured via the `CORS_ORIGIN` environment variable:

```javascript
// In app.js
app.use(
  cors({
    origin: process.env.CORS_ORIGIN,
    credentials: true,
  }),
);
```

### 7. Helmet.js

Security headers are set via Helmet:

```javascript
import helmet from "helmet";
app.use(helmet());
```

### 8. Session Security

Express session is configured with:

```javascript
app.use(
  session({
    secret: process.env.SESSION_SECRET,
    resave: false,
    saveUninitialized: false,
    cookie: {
      secure: process.env.NODE_ENV === "production",
      httpOnly: true,
      maxAge: 24 * 60 * 60 * 1000, // 24 hours
    },
  }),
);
```

### 9. Input Validation

All user inputs are validated using express-validator:

```javascript
// Example validator
const userRegisterValidator = () => {
  return [
    body("email")
      .trim()
      .notEmpty()
      .withMessage("Email is required")
      .isEmail()
      .withMessage("Invalid email format"),
    body("password")
      .notEmpty()
      .withMessage("Password is required")
      .isLength({ min: 8 })
      .withMessage("Password must be at least 8 characters"),
  ];
};
```

### 10. Data Exclusion

Sensitive fields are excluded from all database queries:

```javascript
export const EXCLUDED_FIELDS = [
  "password",
  "refreshToken",
  "forgotPasswordToken",
  "forgotPasswordExpiry",
];
```

## OAuth Security

### Google OAuth 2.0

| Measure         | Implementation               |
| --------------- | ---------------------------- |
| Token storage   | httpOnly cookie (not URL)    |
| HTTPS           | Required in production       |
| State parameter | Required for CSRF protection |

### Access Token in Cookie

The OAuth callback now sets the access token as an httpOnly cookie instead of passing it in the URL, preventing token leakage:

```javascript
res.cookie("accessToken", accessToken, {
  httpOnly: true,
  secure: process.env.NODE_ENV === "production",
  sameSite: "strict",
  maxAge: 15 * 60 * 1000, // 15 minutes
});
```

## Security Checklist for Production

### Environment Variables

- [ ] `NODE_ENV=production`
- [ ] Strong JWT secrets (min 32 characters, random)
- [ ] Strong session secret
- [ ] `CORS_ORIGIN` set to specific domains (not `*`)
- [ ] `secure: true` for cookies

### Database

- [ ] Use dedicated database user with minimal permissions
- [ ] Enable SSL/TLS for database connections
- [ ] Regular backups scheduled

### Server

- [ ] HTTPS enabled (TLS 1.2+)
- [ ] Security headers (Helmet)
- [ ] Rate limiting enabled
- [ ] Request logging enabled
- [ ] Error logging without exposing stack traces

### Application

- [ ] Input validation on all endpoints
- [ ] Error responses don't leak sensitive data
- [ ] Tokens not logged
- [ ] Password requirements enforced
- [ ] Account lockout after failed attempts (future enhancement)

## Security Headers

Helmet sets these headers:

| Header                    | Value                               |
| ------------------------- | ----------------------------------- |
| X-Content-Type-Options    | nosniff                             |
| X-Frame-Options           | SAMEORIGIN                          |
| X-XSS-Protection          | 1; mode=block                       |
| Strict-Transport-Security | max-age=15552000; includeSubDomains |
| Content-Security-Policy   | default-src 'self'                  |

## Logging Security

- Request IDs added to all logs for tracing
- Sensitive data (passwords, tokens) never logged
- Error stack traces logged but sanitized in production

## Incident Response

### If a Token is Compromised

1. **Revoke the token**: Clear the refresh token from the database
2. **Force logout**: Clear all refresh tokens for the user
3. **Investigate**: Check logs for unauthorized access

```javascript
// Clear all sessions for a user
user.refreshToken = null;
await user.save();
```

### If Password is Compromised

1. User requests password reset
2. Or admin deletes/recreates user
3. All refresh tokens are automatically invalidated on password change
